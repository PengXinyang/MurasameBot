# 代理、定时插画和主人转发

公开默认值在 `config.yml`；个人配置写入被 Git 忽略的 `config.local.yml`、`.env` 和 `.secrets/`。以下为可合并到本地配置的独立示例，不要覆盖已有私密字段。模型地址和名称仍由本地变量填写。所有配文保持中文丛雨语气，不启用日语语音或角色服装图片。

## 主人 UID

公开模板使用 `${MURASAME_OWNER_UID}`；在 `.env` 填写自己的数字 UID。当前操作者的原有绑定已保存在 `config.local.yml`，不会提交到 Git。`config.local.yml` 中显式配置的绑定优先于 `.env`；以后更换主人 UID 时修改该本地绑定即可，或删除本地 `bindings` 覆盖后使用环境变量。

```yaml
bindings:
  - person_id: owner
    platform: bilibili
    external_id: "你的数字UID"
    display_name: ""
    purpose: owner_video_recommendation
```

变更或撤销身份绑定会使相应的未完成推荐和主人转发失效，不根据昵称认主人。公开示例、模拟演示和测试使用占位符或虚构 UID。

## 7890 出站代理

```yaml
network:
  proxy_enabled: true
  proxy_url: http://127.0.0.1:7890
```

这个 HTTP 代理同时承载 HTTP 请求和 HTTPS CONNECT。代理服务如果提供 SOCKS5，可把地址换成 `socks5://127.0.0.1:7890` 或 `socks5h://127.0.0.1:7890`。程序已安装 `httpx[socks]`。每次连接使用所选的一种代理协议，并不同时向三个代理发送请求。7890 需要由你安装的代理软件提供相应协议服务，程序不启动 VPN。

范围包括模型调用、B 站登录/读写、字幕 CDN、Pixiv、X 与分享图片下载。CDN 下载使用独立的无账号 Cookie 客户端。代理不可用时请求失败，不自动改为直连。暂未启动代理时设置 `proxy_enabled: false`；不继承系统环境代理。管理台 `127.0.0.1:8766` 和本地测试不经过出站代理。代理配置下一轮生效；带用户名密码的代理地址在管理 API 中脱敏。

## 定时发布角色插画

```yaml
artwork:
  enabled: true
  delivery: image
  times: ["12:30", "20:30"]
  weekdays: [0, 1, 2, 3, 4, 5, 6]
  grace_minutes: 30
  keywords: [千恋万花, 丛雨, 夏日口袋]
  sources: [pixiv, x]
  candidate_limit: 8
  max_caption_characters: 100
  permissions:
    - source: pixiv
      artist_id: "画师的数字ID"
      work_ids: ["已获授权的作品数字ID"]
      evidence: "授权记录地址或本地记录编号；已确认允许署名转载至本账号"
      expires_at: "2027-01-01T00:00:00+08:00"
```

上例的中文 ID 只是说明，请替换成真实数字，否则配置校验会拒绝。`permissions` 为用户核实的授权记录，不由模型推断。`work_ids` 可限定作品范围；仅在确有整个画师作品范围的授权时省略该字段。`expires_at` 可省略表示未设置到期时间。删除授权、更改授权范围或到期后，待发布图片在发送前会被阻止。画师昵称不能代替数字 ID；仅找到链接或署名不被当作转载授权。

来源凭证在本地 `.env`：

```dotenv
MURASAME_PIXIV_SESSION=
MURASAME_X_BEARER_TOKEN=
```

Pixiv 为只读网页 AJAX 搜索，可填写自己的 `PHPSESSID` 值；匿名访问若受限则提示更新会话，不绕过登录、验证码或访问限制。X 使用官方最近搜索接口，需自己的 Bearer Token 和相应 API 权限；收费与可用配额以 [X 官方说明](https://docs.x.com/x-api/posts/search-recent-posts) 为准。Pixiv/X 会话失效与来源访问失败会记录活动日志，不冒充搜索成功。

每个时刻轮换一个关键词，每来源只查一页有界候选；先检查安全分级、插画类型、推广/成人/AI 标签、授权及去重，再让模型判断是否为游戏角色同人图并生成中文配文。一次时刻最多生成一条分享。未找到合适且获授权作品就跳过；时段错过超过宽限时间不补发。重启不会重复处理同一时刻，已受理或结果未知的作品不再重复分享。

筛选依据来源元数据及模型分类，尚未实现像素级视觉审核；配文只依据作品标题、角色和标签，不编造画面细节。默认仍为 `mode: draft`，可以先检查草稿中的画师与作品链接。`mode: auto` 会按同一策略自动发布。不要把“安全模式标签”理解成对图片内容的绝对保证。

发送顺序：独立客户端获取原图 → 验证 JPEG/PNG 文件完整性、10 MB 大小与 4000 万像素上限 → 检查当前授权 → B 站上传图片 → 再次检查授权/暂停/有效期 → 创建图文动态。正文由角色配文、画师署名和原作链接组成，不去水印、不裁图、不改画。授权在上传后撤销时，不再创建公开动态；已上传但未发布的文件可能保留在平台。上传或创建结果不明时保持未知状态，禁止自动重试。

`delivery: link` 仅分享原作链接与配文；`delivery: local` 仅把最近一次发现保存到本地设置与活动记录。用户当前选择为 `image`。开关、时间、关键词、来源和转发开关可以在管理台设置；来源密钥及授权范围仅在本地文件维护。

## 主人新视频、动态转发

```yaml
bilibili:
  owner_new_videos: true       # 主动评论
  owner_new_dynamics: true
  repost_owner_videos: true   # 转发到 AI 账号动态
  repost_owner_dynamics: true
```

四个开关独立。视频评论使用视频评论区 ID；视频转发使用主人空间流中对应的投稿动态 ID；图文动态的评论对象 ID 与动态 ID 同样分开处理。没有找到原始动态引用时不猜 ID，也不调用只增加分享计数的接口。发送前重读原始动态并验证作者仍是主人。

首次启用账号或首次绑定新主人时把已有内容作为基线，不批量评论或转发历史作品；之后发现的新内容才进入队列。转发与评论分别去重，可以同时执行。转发文案由人设生成，缺少字幕/正文时仅表达更新提醒，不声称看完或评价具体情节。

所有评论、推荐、转发和图片动态共用同一发送队列、暂停开关、每日发送总额度（当前沿用字段 `limits.daily_comments`）、最小发送间隔和结果未知状态。定时图片不受视频浏览开关控制。QQ/微信未来可复用发现、授权和配文模块，通过各自发送适配器投递。

## 验证边界

自动化测试覆盖代理握手、来源响应解析、授权范围/撤销、时间窗口、原始动态引用、图片下载无 Cookie、上传后最终检查、正文署名和模糊回执。真实 Pixiv/X 搜索、真实模型与真实 B 站上传/转发尚未验收，仍需要操作者的本地凭证；开发期间没有向任何真实账号发布内容。B 站和 Pixiv 网页接口均可能变化，社区协议资料不等于官方稳定性承诺。
