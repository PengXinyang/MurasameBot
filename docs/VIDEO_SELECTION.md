# 视频自主选片与读取门槛

2026-11-05，D62。用户确认阈值只限制AI自主选片；明确指定的视频请求和真实@/回复通知仍可直接处理。验证及正式加载状态见[验证记录](VALIDATION.md)和[开发日志](DEVELOPMENT_LOG.md)。

## 当前默认流程

1. 原自主浏览或主题推荐取得有界候选列表，保留列表话题初筛。
2. 只取题目、简介、分类、实际作者、播放量/评论数及标签，不取字幕、评论、预览帧或调用视觉/决策模型。
3. 普通候选须两项统计同时**严格大于**配置值，默认播放量`>8000`且评论数`>20`；缺失或无效统计不满足。
4. 入选后才进入原字幕、评论、播放器预览截图和视觉流程；AI可跳过、普通评论、已读评论接话或@主人推荐，仍服从独立动作开关。入选不保证互动。

题目或标签命中配置词表，或者实际作者匹配当前主人绑定/AI账号时豁免热度。默认词表包含千恋万花、galgame、柚子社/ゆずソフト/yuzusoft及Key、TYPE-MOON、SAGA PLANETS、SMEE、枕社、Lump of Sugar等厂牌的部分别名。它不是识别所有厂牌的语义分类器；仅在简介出现词语不享受题材豁免。匹配做Unicode规范化与大小写折叠，短拉丁名称设单词边界，避免把monkey当作Key。

豁免不建立身份、真实观看经历或发送权限，不放松公开话题、隐私、审核、来源/记忆/任务/设置、额度、间隔和unknown保护。主人/AI作品同样保留公开话题规则。通知只授权原账号、内容和回复目标；委托豁免依持久任务、来源事件与人物绑定判断，不能由模型填写task_id或昵称授权。

## 设置

管理台“B站浏览与互动 → 主动评论与接话”可选择模式并逐行编辑豁免词：

```yaml
browsing:
  video_selection_mode: read_then_decide
  video_interest_keywords: [千恋万花, galgame, 柚子社, Key社, 枕社]
  min_video_views: 8000
  min_video_comments: 20
  comment_videos: true
  reply_comments: true
  recommend_owner: true
```

旧配置缺字段时补入read_then_decide和内置词表。词表最多100项，每项1～80字非空文字；空列表关闭题材词豁免，作者豁免保持。原始角色来源与人设不改变。

新模式对视频覆盖旧recommendation_only/reactive_video_comments_only的禁止主动普通评论行为，页面中两项旧规则灰显。选择legacy可恢复旧规则及原私人结果阈值；非视频行为保持原样。自主浏览总开关、分区/时段/每轮上限、兴趣、发布模式和独立动作开关不自动修改。

## 实现与限制

- ContentProvider.preview返回metadata Document，不带评论、图片、视觉或帧上下文；缺少接口时停止该次自主读取，不退回先读完整内容。
- B站读取/x/web-interface/view及/x/tag/archive/tags，后者数组仅由显式allow_list解析。确认标签不存在可降级；网络、认证、限流、冷却及其他错误向上传递。原GET节奏及退避保持。
- 同Runtime最多缓存100份预览，60秒内可复用对应view；预览不存成已分析视频或聊天记忆，不伪造视觉证据。没入选不记成已看，之后热度增长可以重新判断；候选和完整读取分别受candidate_limit/videos_per_round约束。
- Document.tags兼容旧JSON缓存，无schema迁移。成功读取后缓存保留用于选片的作者、题目、标签、统计；最终发送按当前策略/绑定复验，人工批准也不能绕过其他门禁。
- 复用原唯一协调器、模型限流、审核、outbox及串行sender；主人视频原发和转发入口同样检查真实元数据。不增加第二套AI或sender。
- 观察主题推荐保留原授权用途，只能推荐或跳过；本轮不扩大私人观察对公开评论的用途。

“读取/看视频”仍是当前可得简介、部分字幕和离散预览截图，不能称为完整观看；没有下载视频、音频理解或实现[后续视频理解方案](VIDEO_UNDERSTANDING_PLAN.md)。
