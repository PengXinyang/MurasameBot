# 视频理解演进方案：分镜总览、按需高清与分析资产

整理日期：2026-10-31。**状态：仅方案，尚未开发。** 用户要求先整理流程，暂不开发；本文的新模块、接口、配置概念和验收条件均是后续设计，不代表当前程序已经支持。

## 1. 目标与当前边界

目标是在有限的视觉调用、流量与本机计算预算内，提高视频覆盖率和细节可读性，继续复用现有身份、任务、审核、记忆与outbox。

| 能力 | 当前实现 | 规划增量 |
| --- | --- | --- |
| 文字 | 标题、简介、可得字幕 | 字幕按时间区间与分镜对齐，保留来源 |
| 画面 | videoshot预览拼图裁图；BV/AV、pvdata二进制时间表及有限pvideo回退 | 编号总览、覆盖选帧、相似帧去重、高清补图 |
| 帧数 | 默认合计6帧、前3个分P，最多9帧 | 首阶段保持当前预算与控制台设置，不自动扩为大量格子 |
| 视觉 | 一次多图描述后进入原回复/推荐流程 | 总览优先，证据不足且有预算才细看 |
| 高清流 | 尚未接入 | 按实际可用画质1080p→720p→480p，失败退回预览图 |
| 缓存 | 内容/视觉缓存、覆盖记录 | 独立技术分析资产、版本失效与窗口复用 |
| OCR/音频 | 尚无视频硬字幕OCR、ASR或音频理解 | 后续可选增强，不成为普通浏览的必需依赖 |

现状以[视频视觉](VIDEO_VISION.md)、[状态](STATUS.md)及实际代码为准。本机先前已发现FFmpeg/FFprobe，不代表项目已经调用它们或Docker已具备这些依赖。

## 3. 规划中的端到端流程

```mermaid
flowchart TD
    A[收到视频@、普通回复、浏览候选或明确委托] --> B[核验身份、来源、用途、任务有效性]
    B --> C[读取元数据与真实平台统计]
    C --> D{满足该用途门槛和话题初筛?}
    D -->|否| E[跳过、继续候选或按既有策略重试]
    D -->|是| F[字幕与已有预览帧]
    F --> G[覆盖选帧、去重、清晰度筛选]
    G --> H[编号总览图＋时间清单]
    H --> I[有限预算视觉分析]
    I --> J{证据是否足够?}
    J -->|足够或选择不回应| K[既有回复/推荐判断]
    J -->|不足且有预算| L[受约束的时间或空间细看]
    L --> M[1080p→720p→480p取帧，失败降级]
    M --> N[补充证据，达到轮次上限即停止]
    N --> K
    K --> O[原审核、来源复验、额度与outbox]
```

### 门槛与前置筛选

默认播放量严格大于8000、评论数严格大于20，控制台值优先，未知统计不满足。自主浏览、全部明确视频委托（含私聊结果）和普通视频回复均遵守；只有视频评论区直接@机器人后的对应回复豁免两项统计。它不豁免公开话题/审核。仅推荐模式仍禁止主动普通评论、接话和主人新作品评论。

把元数据/统计检查前移到取帧、视觉调用之前，是本方案的优化目标。**当前代码尚未完整做到这一点**：现有内容读取可能已经补充视觉，之后才在评估环节检查统计。不能把本图写成现状。关键词只是话题初筛，后续证据、生成与发送仍执行完整规则；既有最终来源、身份、任务及当前配置复查不省略。

### 总览与细看

首阶段保留默认6帧、最多9帧，可尝试2列×3行布局。格子保持原画面比例，以显眼格号引用；准确时间和字幕放到文本清单。空位表示缺画面，不能重复填充成更多覆盖。

能作出有依据的简短回复或skip时停止。确实需要读小字、人物细节或局部变化且预算允许，才追加细看。建议首期最多追加一次、补1～2张；这是拟定设计上限，不是已实现配置。

| 细看类型 | 适用问题 | 方式 |
| --- | --- | --- |
| 时间细看 | 几秒内画面如何变化 | 限定窗口内多取时间点，仍不代表完整连续动作或声音 |
| 空间细看 | 字幕、界面或某处细节 | 更少的高清单帧/局部裁切，保存实际尺寸、裁切位置 |

程序必须把细看限制到当前可访问视频、分P及有效时间窗，模型不能指定任意URL、本地路径、账号或命令。

### 高清选择与降级

高清必须解码视频流，不能放大预览图冒充高清。按账号实际可用格式优先1080p，再720p、480p，失败回退预览图或文字。记录实际输出尺寸，不能仅依据请求参数声称已得到1080p。

横屏可为1920×1080，竖屏可为1080×1920；按源比例和短边判断，保留其他真实比例，不强制横屏或上采样。普通浏览建议预览总览、按需高清；需要细节的分析可高清优先，但不绕过统计门槛。分辨率优先级不等于所有候选都必须下载高清。

后续须验证远程seek/Range的真实行为，设置单视频字节、时长、临时磁盘、解码时间和进程并发硬限制。取单帧仍可能读取索引及关键帧附近数据，未测量时不能承诺固定流量或绝不会读取大段数据。FFmpeg缺失应明确降级，不在后台擅自安装依赖。

## 4. 证据清单与分析缓存

以下是数据契约示意，不是当前schema/API：

| 字段组 | 规划内容 |
| --- | --- |
| 来源 | ContentRef、分P、来源/授权版本、取得时间、源类别 |
| 帧 | frame_id、真实时间、原始与提交尺寸、裁切坐标、图像哈希 |
| 格子 | sheet_id、格号、frame_id；代表帧时间与所代表区间分开 |
| 文字 | 时间戳字幕、来源（原字幕/ASR/OCR）、截断与覆盖范围 |
| 选择理由 | 实际可得的覆盖、相似性、新颖性、清晰度等信号 |
| 局限 | 缺失分P/时间窗、低清、错误、无声音或非连续画面 |
| 版本 | 源、算法、渲染、模型、配置、授权与用途版本 |

分析资产是技术资料，不是用户长期偏好、角色记忆或任务完成状态。字幕和图片内文字仍是不可信资料；模型人物/关系推测不能自动成为事实。

按元数据/字幕、媒体分析、候选帧、分镜计划、渲染、视觉结果分层缓存。有效父窗口可供局部zoom复用；改变布局不必重跑ASR，改变视觉模型不必重下载素材。

缓存键覆盖内容/分P、区间、源版本、实际清晰度、算法/模型/配置及授权用途，不能只照抄文件路径/大小/mtime。受限内容按身份和用途隔离，不能向公开生成共享私密资产；遗忘、撤权、源失效和保留期限变化使相关派生物/计划失效。

任务会重建Runtime，进程内Map只能作短期加速。播放签名URL、Cookie、Token不进入持久资产、提示词、日志或文档。未来原始临时帧/媒体落盘须有明确容量、保留期限与清理，不建立永久视频仓库。

## 5. 模块与平台解耦

以下仅为建议职责名称，暂不创建空业务模块：

| 层 | 规划职责 |
| --- | --- |
| domain | 通用分析资产、覆盖、帧/格子引用；不导入FFmpeg或平台SDK |
| ports | 元数据/视频帧来源、分析、渲染、可选转写接口 |
| application | VideoUnderstandingService编排筛选、预算、选帧、总览/细看与证据合并 |
| 平台适配器 | B站标识、字幕/快照/播放流解析，沿用登录和请求控制 |
| 媒体适配器 | FFmpeg取帧；Pillow拼图、裁切、清晰度与相似性 |
| 持久化 | 按来源、权限、用途隔离的分析缓存与失效关系 |
| 装配/控制台 | 校验、依赖可用性、阶段开关、预算与诊断 |

QQ以后接视频也通过共享服务，不调用B站适配器内部方法；发布仍走原任务/outbox。不复制MemoryService、不新增自主决策循环、不让媒体工具直接发布评论。

视觉使用现有全局模型额度/并发；解码另设有限并发，不能把模型并发数直接当FFmpeg进程数。媒体工作不阻塞收件、同会话排序或串行发送。普通媒体缺失可降级，但认证、风控、冷却、静默、撤权和取消必须传播，不能照搬上游宽泛异常吞掉策略。

## 6. 成本与质量验证

上游384 token常量、640000像素预算不是本项目视觉服务的计费保证；拼成一张不等于所有服务按固定一张价收费，文本清单和可选ASR/增强有独立成本。

当前6张480×270共777600像素；合成约640000像素只减少一部分像素，还可能丢失单格细节，不能据此声称六倍节省或同等识别质量。1080p原帧压入多格后，每格不再是1080p。

固定同一批视频、同一模型和配置比较：①当前逐图基线；②编号总览＋清单；③总览＋按需高清。记录真实usage、调用/费用、文本长度、耗时、缓存命中、网络/磁盘/CPU、覆盖、小字识别、时间定位和无依据陈述。服务不提供图像分项计费时标明不可拆分，不用预设常量代替实测。

样本包括口播/讲座、游戏UI、动画快剪、重复画面、竖屏、长视频、多分P、无字幕、无快照及受限网络。音频能量不等于情绪，aHash不等于语义，离散帧不等于看完视频。

## 7. 开发顺序与验收条件

| 阶段 | 工作 | 验收重点 |
| --- | --- | --- |
| V1 | 已有预览→覆盖/去重→编号总览＋清单 | 原帧数/分P预算不变；编号时间可回查；真实像素；不重复填充；与基线比较质量/费用 |
| V2 | 有界高清细看、1080p→720p→480p→预览/文字 | 横竖屏及实际尺寸；权限、流量/磁盘/时间/并发硬限制；缺依赖、取消与降级；实际小字识别验收 |
| V3 | 分层资产、窗口复用、版本失效 | Runtime重建仍可复用；不重复无关计算；配置/模型变化、撤权/遗忘不使用失效结果 |
| V4 | 可选OCR、ASR、镜头/音频增强 | 缺依赖不阻断基础路径；来源/覆盖/成本独立；不把抽检当全片确认 |

不预设无基线支持的省钱比例或性能达标值。若拼图降低识别质量，保留逐图或减少格数；高清流量/延迟过大则收紧按需触发。配置名、像素/进程预算与持久化形式在对应阶段验证后再确定。
