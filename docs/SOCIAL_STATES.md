# 带来源的社交事件与短期角色状态

实现日期：2026-10-29。用户明确要求收到社交信息后决定是否在意、询问或以后自然提起，并允许吃醋剧情出现在公开动态。本模块管理角色的短期反应，不把反应保存成永久人设、用户事实或任务。

## 使用

完整重启工作循环后，管理台新增“心情与线索”。可以查看来源摘录、来源类型、可信程度、心情、最早跟进时间、有效期和已提起次数，并执行“结束这段心情”或“遗忘这条线索”。参数均可在该页设置：

```yaml
social:
  enabled: true
  public_posts_enabled: true
  private_feelings_public: true
  ttl_hours: 24
  retention_days: 7
  context_limit: 6
  max_active_states: 20
  max_followups: 2
  followup_min_minutes: 15
  followup_max_minutes: 720
  followup_gap_minutes: 120
```

普通回复中的判断不另调用模型：原有回复JSON可附`social_update`。默认不记录普通流水聊天；模型可以不在意、只记录感受、在当前回复中自然询问、安排稍后提起，或结束已有状态。无效侧输出只写脱敏诊断，不使正常回复进入失败重试。

主动公开表达仍须开启`autonomy.dynamic_enabled`；主动私信仍须开启`autonomy.private_enabled`和私信总开关，且只给实际绑定、互关的主人。原自主时段、私信安静期、每日计划数、模型预算、发送冷却、审核与全局间隔全部保留。`social.public_posts_enabled`不代替动态总开关。可以只记录并用于正常聊天，而不主动发布。

15分钟是默认最早跟进时间，不是保证15分钟时发送。后台协调器在下一次允许的检查中判断，私聊仍可能等待默认60分钟安静期；每日额度、动态/私信冷却和发送队列也可能推迟。没有值得说的内容可skip。没有增加独立轮询、独立发送器或每条消息的第二次模型调用。

## 来源与可信程度

应用服务为`application/social.py`，端口为`SocialRepository`，SQLite实现为`adapters/persistence/social.py`。

- `message`：当前实际来信的一段精确连续原文，绑定身份由程序解析。主人自己说的话标为`owner_statement`，其他人提供的信息保守标为`reported`，不自动升级为已核实事实。
- `content`：实际读取的动态/内容正文，或已提供的相关父评论。选择评论必须引用真实`source_comment_id`；保存内容引用和评论ID，不接受模型编造的楼层。
- `visual`：成功视觉分析中的原文，保留原内容引用；只有截图计划、空分析或失败帧不能形成视觉来源。截图中的昵称不能证明主人身份。
- `owner_observation`：实际授权的观看记录标题，保存观察记录ID、授权/用途版本和本机核验锚点，不伪造聊天。仅在允许的主人私聊生成中产生；历史吃醋仍要求原`playful_jealousy`开关和至少三个不同视频，模型还须遵守主题证据与不推断敏感身份的规则。

主人的澄清可结束与主人有关的状态；其他人只能澄清自己在同一会话提供的信息。仅允许模型选择本次实际提供的状态ID并按版本处理，较早发生的迟到消息不能结束更新来源的状态。转述“可能与主人有关”不授予发言者主人身份、私人记忆访问权或私信投递权。

## 公开吃醋与私人来源

公开动态可以表达自己的轻微吃醋、撒娇、好奇和想念。公开来源可以保留带归因的摘录；传言仍须保留不确定性。人物身份不因模型联想而确认。

对主人的私人来信或授权观看线索，`private_feelings_public=true`允许程序进行有损投影：公开模型只收到状态ID/版本、心情标签、强度、在意方式和提起计数，以及只能表达自身感受的规则。不会收到私人摘录、事件ID、会话、备注、原始观看标题、人物、具体时间或私密行为。独立审核也使用同一投影，不为审核重新提供原始私人信息。

因此可以生成“吾辈也想多分一点主人的注意呀”这样的公开心情，不应把一个感受标签补写成“主人昨晚去找某人聊天”。第三方私聊不因此对主人或公众开放。固定角色文件、私人观察日记和私密关系人设均不作为这项投影的输入。

## 状态与计划生命周期

`social_events`保存来源、摘录、归因及保留期限；`role_states`保存有时效的`notice/ask/later`反应、心情、备注、版本、最早跟进时间和提起计数。两张附加表在现有v2数据库上事务创建，原数据库/档案不重建。

状态默认有效24小时，来源摘录默认保留7天。到期状态不再进入上下文或发送；清理由相关读取、提交和来源维护触发。状态到期清除心情备注，来源保留期到期清除摘录。来源ID幂等，遗忘保留墓碑；相同事件重试不能重建已遗忘或已到期状态，新的真实来信属于新的来源。

当前回复、自主动态和主动私信都可声明实际采用的状态ID。计划引用状态版本与社交设置版本，走原outbox，生成后入队、领取和最后写入前复验。结束/遗忘、原消息遗忘、更正相关记忆、身份解绑、观察清除/撤权/过期都阻断旧计划；人工审核与重发不刷新这些依赖。

同一状态已有草稿、排队、审核、发送中或unknown的提起时，不再生成第二份主动计划。仅平台受理才增加提起次数并推迟下次时间；这不等于独立验证客户端送达或公开可见。达到默认累计2次提起后停止主动跟进，普通新来信仍可正常回应，不强制结束所有正常聊天。失败、草稿和unknown不算已说过；unknown仍占住主动计划，禁止自动重发。

“结束心情”取消后续使用但保留本机来源；“遗忘线索”清除社交摘录/备注及相关本地待发文字，不删除原聊天或已在平台发出的内容。要遗忘原聊天，在记忆页操作其来源。公开/私人提示词仍由程序筛选，原始记录与短期角色状态不会自动变成事实、偏好或找视频委托。

## 验证与边界

专项包含来源归因、当前正文/实际父评论/真实视觉、第三方私聊隔离、公开投影、主人澄清与迟到消息、同源重试、过期与遗忘、身份变化、记忆更正、观察更新/清除/权限、当前回复/主动动态/独立审核、人工重发、平台受理计数、unknown防重、配置与管理台鉴权。完整测试与浏览器结果见[验证记录](VALIDATION.md)。

未运行真实模型或真实账号发布；真实角色语气、是否自然询问及公开表达的质量需后续体验。平台已经发生但程序尚未获知的内容删除不能即时发现，不保证模型判断或敏感主题识别无误。QQ、微信和X的真实收发仍未接入；本模块通过统一事件和端口为后续适配复用。
