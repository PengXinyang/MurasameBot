## 页面归属

| 分组 | 页面与内容 |
| --- | --- |
| QQ | 私聊与消息：连接配置状态、机器人/主人绑定、只读账号与好友核验、静默合并设置、合并中/待处理消息、最近聊天及发送回执；QQ视频委托：预约、查找、审核、完成、取消与实际投递渠道 |
| B站 | 浏览与互动、发布与互关私信、B站发起的视频委托、主人足迹；原通知、互动、请求诊断及插画入口保留 |
| 共同模块 | 记忆、日记、相处回顾、心情与线索、模型与共同设置 |
| 工作台/系统 | 跨平台运行概况与活动记录 |

任务按发起平台归属：QQ里要求“在B站提及”的委托仍在QQ委托页管理，标出“QQ发起→B站公开提及”；实际公开发送在B站发布记录中也可核查。没有持久路由的旧任务仍在原目标平台显示。取消复用原任务接口，不在前端自行改状态或直接向平台发送。

QQ模块可单独开关；静默窗口、最长合并等待、单轮最多回复条数仅保存QQ设置，不改B站。账号、接口地址与两个密钥仍由本地私密配置管理。只读核验不发送消息；“已配置”“模块已启用”“上次核验通过”均不表示网关/接收器/工作循环现在在线。页面不自动启动它们。

模型、审核、发送额度、视觉、表情及视频查找时段/未命中重试间隔影响两端，放入共同设置。B站保存只提交平台相关字段；QQ保存不带B站字段；共同设置不覆盖账号/凭证或QQ合并参数。配置字段和原执行语义保留。QQ明确视频委托继续独立于一般自主浏览开关，公开B站规则不变。

## 共同记忆来自QQ和B站

两个平台的聊天归档进入同一`conversation_records`/`MemoryService`。同一已绑定主人私人对话可按原授权跨平台回忆；公开/私人、其他人及观察日记的边界不因页面合并而取消。失败、草稿和unknown回复不算已经说过的话。

原文即时归档后，摘要/事实按既有阈值和预算整理；日记与相处回顾在配置的每日回顾时刻/维护通道生成，不保证每条来信立刻产生一篇。事实仍要有用户原文依据，来源删除/遗忘会使相关产物失效；不使用日记替代任务状态。

记忆、日记、相处回顾都有“全部平台 / QQ / B站”来源选择，三个页面同步选择。来源筛选在数据库限量之前执行，避免最近的B站条目挤掉QQ记录。条目显示真实来源平台，并可查看对应原文；观看观察日记仍单独标注且需有效授权。

跨平台输出按实际投递平台与可见性归档，并保留原委托来源关联。QQ发起、B站公开发送的推荐不会再当成QQ私聊回复，也不会把原私人委托正文写成公开对话。

## 文件与接口

- `bilibili-console.js`、`qq-console.js`分别负责平台控件和展示；`console-common.js`负责共同设置/行渲染，`shared-memory.js`负责共同记忆操作。
- 鉴权的`GET /api/platforms/qq`和`GET /api/platforms/bilibili`提供有界、按agent与来源筛选的任务/动作/归档投影。
- `POST /api/qq/check`仅核验配置机器人与主人好友；`GET /api/memory/journals?platform=qq`等接口按原文来源过滤。
- 新静态资源使用明确允许列表并纳入Python包资源；不开放任意文件读取。
