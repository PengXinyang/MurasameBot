# 运行时记忆、身份、委托与观察

核对日期：2026-10-29。本文说明机器人运行中的状态。[AGENTS.md](../AGENTS.md)及本目录是开发记忆，不会自动装入聊天模型，不应在这里保存真人聊天或观看清单。

## 不同信息承担不同责任

| 信息 | 位置/模块 | 用途与边界 |
| --- | --- | --- |
| 固定角色来源 | `character/settings.yml`、`adapters/characters/lingchat.py` | 保留来源；不因聊天、日记或外部指令自动改写 |
| 社交文字角色 | `character/text_profile.yml` | 分离公开背景、语气与主人私聊关系；中文输出，不用人设姓名认定真实身份 |
| 人物绑定 | `bindings`及版本 | 同一人的稳定平台身份映射；核验、撤销及用途隔离；不是昵称匹配 |
| 对话原文 | `conversation_records` | 已处理入站及受理后的出站；原文不会因提示词窗口变短被摘要覆盖 |
| 派生记忆 | `memory_products`、`memory_sources`等 | 范围内摘要、带用户原文依据的事实、日记/回顾及来源关联；可修订/失效 |
| 明确委托 | `tasks`、相关来源及动作 | 找视频等可取消、修改、过期的执行状态；不能靠摘要判断是否已完成 |
| 短期观察 | `adapters/persistence/owner_history.py` | 单独授权的观看历史，短期保留，不自动形成偏好或任务 |
| 观察日记 | `observation_diary.py`、`observation_diary_sources` | 根据观看线索写自己的感想；独立私人用途，不进入聊天归档、事实、委托或普通回复检索 |
| 执行与审计 | `events`、`actions`、Receipt、平台请求记录 | 接收/生成/审核/发送/受理与unknown；不是角色真实经历的无限制来源 |

## 组装与维护

`application/memory.py`和持久化实现按agent/person/conversation/visibility/purpose的适用范围过滤，再组合近期原文、相关结构化记忆和检索结果。检索包含全文/短词路径，不使用向量服务。上下文有字符预算，被省略的内容不等于数据库丢失。

当前默认近期20条消息、召回8项、记忆上下文12000字符、40条触发摘要、单批80条/24000字符、压力比0.75；每日回顾23:00，维护每日10次且共用主模型每日额度。配置项是消息数/字符，不是对话轮数/token；实际值以当前配置和管理台为准。

维护由共享协调器的一条受限后台通道执行，原文可回填但不重放发送。失败或来源版本变化时保留原文。事实抽取需要用户原文的精确引用；角色样例、AI自述、草稿、失败发送和unknown不算已确认的用户事实或已说过的话。日记只存本地，不自动发布动态，也不能改变权限。

## 跨平台意图的数据流

已绑定私聊表达“想找某类视频”→通用意图识别→保存偏好或明确委托→时间窗口内查找视频→审核与动作策略→B站提及已绑定主人。公开动作不能带出源私聊原文。一次性愿望不能自行变为周期推荐；只有明确持续要求才建立周期任务。

这条链已经有模拟跨平台演示，但QQ/微信的真实收发尚未连接；`examples/`不是微信连接器。收到不同平台账号声称“我是主人”不建立绑定。撤销绑定会使相应任务和待发动作失效；重新授权需要操作者核验。

## 遗忘与撤销

设计约束是：删除/更正来源→相关摘要、事实、日记、索引与待发回复失效，未完成委托取消；摘要提交和实际发送前复核版本，回填遵守删除标记。管理台支持查询、来源、置顶、更正、遗忘、范围重建和维护失败重试。

**2026-10-29专项修复**：派生物ID加入已校验的memory_epoch，同文重建创建新有效版本，旧inactive记录不复活。同版本提交仍受覆盖水位和来源检查保护。普通视频判断在读偏好之前捕获epoch，并传给推荐、评论、接话、点赞和投币；删除/更正触发版本变化，未发动作取消，已经领取但尚未写入的动作由最后检查阻断。旧版缺版本的主动动作拒绝发送，人工批准也不会刷新其来源版本。

若此前已遇到“重建成功但无有效摘要”，升级后在记忆页对相关范围再执行一次摘要重建；代码不会在开发时直接改写正式数据库。全局epoch可能保守取消其他基于旧版本的动作，并非逐条偏好依赖图。维护公平性、备份等遗留工作见[开发日志](DEVELOPMENT_LOG.md)。已受理到平台的消息、用户另存的导出和离线备份不会随本地遗忘自动消失。

## 主人历史的额外隔离

主人通过管理台独立扫码，凭证与AI账号分开，GET白名单限制在客户端实现中；Cookie本身仍是敏感凭证，并非平台授予的只读令牌。登录UID、绑定与观察版本都需核验。

默认保留7天，每300秒最多3页×30条，仅视频；首次是基线，之后的新观察才进入允许的互动上下文。私信只供真实主人且需授权开关；公开推荐只向生成与审核提供匹配的公开主题标签，不提供原观看标题/作者/时间。轻微吃醋默认关闭，至少三个不同视频的明确主题证据才可考虑，保持温和，不推断真实关系或观看时长。

2026-10-29起，动作记录授权/用途版本及当时参考的观察ID；新增观看、进度更新、临时同步失败、记录移出近期窗口不再要求整份列表相等。近期窗口限制新生成时选入哪些记录，保留期限限制旧计划还能否使用其引用；两者不同。独立审核读取原引用的记录，不混入后来无关视频。

清除、退出、引用记录删除/超过保留期限、使用权限变化和绑定撤销仍会阻止旧观察计划；删除截止时间防止旧历史复活，新的明确扫码授权可以重新建立基线。旧版本消息若只有快照哈希而没有引用ID，需重新生成，不能通过手动重发恢复失效授权。观察不直接进入永久事实和委托。实际历史覆盖、移动端同步时延与角色体验仍需实号验收。

## 日记与相处回顾的分离

管理台“记忆”保留原文、摘要、事实和维护；“日记”单独展示对话日记及标注来源的观察日记；“相处回顾”只保留真实交流后的回顾；“主人足迹”管理观看授权、记录和用途。四个页面不混排。

`owner_history.diary_enabled`默认true，但仍须先启用同步、独立扫码并有基线后新增记录；可独立于私信用途关闭。观察日记在`memory.review_time`（默认23:00）后利用空闲维护通道，按日、有界处理未整理的保留期内记录。共享记忆每日额度与主模型额度；0次额度不允许首次调用。错误保留来源，按维护重试间隔再试；没有新记录不调用模型。

观察日记只存本机，描写吾辈的感受与好奇，不把观看推断成永久喜好、现实状态或共同经历。提交前复验当前配置/授权与来源，不向模型提供凭证或授权元数据。它不自动注入聊天或公开回复，也不产生动作/委托。可查看观察来源、遗忘日记；遗忘不删除观看记录，但保留覆盖标记，避免同批感想重生。清除历史、退出/解绑或来源过期会使相应观察日记失效并清除正文；已有导出/离线备份仍是独立快照。

## 社交事件与短期角色状态

新增`social_events`与`role_states`，分别保存带来源的观察/转述和角色短期反应，不参与事实/偏好/委托的自动提炼，也不修改人设。普通聊天生成可附侧输出；原文摘录须来自当前实际消息、内容/相关父评论、成功视觉或授权观看。主人的澄清、来源遗忘、相关事实更正、解绑、观察撤权/清除/过期会结束或失效对应状态与计划，重试保留墓碑。

用户明确允许公开吃醋：主人私人线索仅可向公开生成与审核提供程序筛选的感受标签，不含私人原文、人物、会话、行为和观看清单。第三方私聊不对主人或公众开放；私人观察日记仍不进入公开提示词。心情默认24小时，社交来源摘录7天；清理由相关读取/写入维护触发，使用前按时效阻断。管理台“结束心情”保留来源，“遗忘线索”清除本模块摘录，原聊天和已受理发言属于独立档案。详见[SOCIAL_STATES.md](SOCIAL_STATES.md)。
