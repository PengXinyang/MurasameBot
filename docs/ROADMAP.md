# 后续范围与实现边界

更新日期：2026-10-30；已有能力快照仍以2026-10-29核对结果为准。这里只记录已明确的后续方向及代码确认的缺口，不给未商定的日期或平台可用性保证。当前问题见[开发日志](DEVELOPMENT_LOG.md)。

## 当前主线：QQ接入与平台解耦

按2026-10-30用户要求，QQ优先于旧建议中的Docker及其他平台接入。Q0平台装配/能力/配置与领取路由隔离已编码，B站协议文件保留原样，真实QQ仍未接入。接下来Q1真实文字私聊，Q2跨平台委托来源/结果渠道分离，Q3主动/图片/群被动回复，Q4分别评估群自主参与、语音与空间。采用一个应用中的独立平台模块，不复制内核、不立即微服务化。详见[QQ方案](QQ_INTEGRATION.md)、[平台模块说明](PLATFORM_MODULES.md)与D30/D31。

下列既有验收、维护、备份与部署缺口继续保留，但不是开始QQ开发前必须全部完成的串行前置条件。

## 持续验证现有闭环

摘要同内容重建与普通推荐偏好失效已于2026-10-29专项修复，后续持续保留反例回归；下一步改善维护公平性和备份恢复，逐项实号验收主人观察、主动私信、公开评论/互动、授权图片搜索发布与长期限流恢复。现有测试为模拟与本机接口，不能替代这些验收。

## 后续真实平台接入

| 用户已要求记录的方向 | 当前边界 | 复用点 |
| --- | --- | --- |
| QQ自主聊天、消息、空间动态 | 尚无真实QQ/OneBot适配器；不实现于本次文档任务 | 稳定身份、事件、记忆/委托、自主计划、审核/outbox；平台协议独立 |
| 微信聊天、主动消息、朋友圈 | 只有统一事件模拟；未接真实微信读取/发送 | 私聊范围、跨平台主人绑定、明确需求到B站推荐；不公开源私聊 |
| X自主动态/消息 | 已有X插画搜索来源，不等于已支持X社交写入 | 通用调度、发布策略、回执；新增X平台适配器 |
| AI作为UP主制作/上传视频 | 对话研究过参考方向，当前只实现文字动态/授权图片发布 | 可复用计划与审核，但生成、素材权利、渲染、上传应独立设计 |

跨平台“微信表达想看某类视频，稍后B站@主人”已有通用任务链与模拟演示；仍需真实连接器、核验绑定、撤权/遗忘及实际送达验收。不得给平台插件各建一套记忆和独立自主循环。

## 部署与长期运行

Docker是用户计划部署方式，但当前没有Dockerfile/Compose；需单独设计容器管理台监听与鉴权、数据/凭证挂载、时区、二维码展示、健康检查、宿主机7890可达及Linux验收。不能把容器内127.0.0.1等同宿主机。CI工作流、长期负载/故障注入、自动备份恢复尚未完成。

精确token预算、向量语义召回、原文保留/冷热存储与更完整的插画像素内容筛选属于已记录的改进方向，并非现有必要运行依赖。

## 明确暂缓或不要求

- 日语仅预留未来QQ/微信语音生成，当前没有TTS/语音模型接入；所有文字继续中文。
- 角色服装、自动头像和表情图片消息暂缓；平台头像由用户手动设置。装饰素材只在本机管理台展示。
- 视频不用完整观看；已有标题、简介、可得字幕及播放器预览多帧视觉，见[视频视觉](VIDEO_VISION.md)。高清按需抽帧仍待做；整段视频下载/ASR不属于当前实现。
- 不把“吃醋”做成对主人关系的控制或羞辱；只能依据授权范围内的观察温和互动，缺少证据时不猜测。

后续接受新需求或改变上述边界时，先更新[决策](DECISIONS.md)，实施后更新开发日志和验证说明。
