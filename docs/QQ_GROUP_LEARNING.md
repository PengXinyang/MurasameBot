# 群聊节奏与表达、黑话学习实现方案

2026-10-31：按用户要求恢复G1～G3开发。参考[Tulpa群聊回合](https://github.com/fumingyang2004/Tulpa/blob/main/doc/MCP_CHAT_TURNS.md)及[实时语言学习](https://github.com/fumingyang2004/Tulpa/blob/main/doc/MCP_LANGUAGE_LEARNING.md)，借鉴机制，自行实现，不复制其人设、源码或独立MCP宿主循环。

实现顺序：先在原群窗口加入节奏统计、有限wait，再建立同库的有来源学习批次/候选/人工修订，最后接入回复和管理台。真实群学习只处理已启用白名单群的实时文字，不拉历史、私聊或机器人输出。学习沿用唯一协调器的空闲维护通道及全局模型并发/预算，每次至多一个阶段，新来信/审核优先。

实时缓存至少40条（仍有时间上限），回复只读取配置的上下文条数；缩短回复窗口不会截断学习采样。每批默认至少6条、最多20条、最多16000字；提取和核对分别调用模型，均为顺序自检，不能称独立核验。原文证据最多24小时/每群100批，抽象知识保留来源ID/引文哈希。表达与黑话分开，逐字引文必须属于当前批，模板固定部分必须在原话；策略指令、账号、人名/私人信息不得成为表达。黑话须多批观察，默认3批且本批核对通过才可用。人工更正/停用不被自动覆盖，忘记来源和记忆修订阻断旧知识/回复。

同一个AI仍只用共同数据库；按agent/机器人账号/群隔离，未授权群不检索；群知识不进入私聊、B站或空间。回复只给少量可选表达和匹配到的可用黑话，可以完全不用。管理台提供开关、预算、观察/可用状态、证据来源、人工修订/停用/遗忘。已完成的抽象知识重启保留，在途结果须复验当前配置、epoch和有效原文，过期/迟到结果拒绝。

节奏采用实际近期消息间隔和连续发言统计，不画像群友或训练模型。小样本保持原静默参数，足量后在有界范围调整；模型可wait，单个修订至多两次，到期重新判断且仍受每群判断间隔/预算；新消息照旧使旧回复失效。

模拟验证与实群自然度分别记录；本次不启用真实群、不发真实消息。

## 配置与使用

在QQ管理页「群语言学习」中开关和调整参数。qq_learning默认enabled=true，仅在qq_groups.enabled、明确群白名单和QQ平台均启用时生效，不会自动收取其他群。默认min_messages=6、batch_messages=20、hourly_calls=12、jargon_batches=3；这表示阶段数而非成功知识数，提取/自检各用一次，失败最多两次且间隔60秒。原证据过期后界面仍保留来源ID与引文哈希，实际原文显示不可用。禁用/更正会提升共同记忆版本，旧生成结果须重新验证；删除来源或清空记忆后，旧版群知识不再检索，属于保守的整体失效。

学习依赖实际实时材料，不把“等待积累”视为故障，不会为了达到门槛回填历史。固定人设不改写，不训练模型，顺序自检仍可能判断错误。人工修订不被新自动结果覆盖，停用/遗忘保留阻止自动复活的条目；现有管理台来源按钮只返回当前授权群仍有效的证据。

节奏当前提供近期消息数、参与人数和间隔中位数；至少6条后静默收集等待按间隔在2秒到原quiet_seconds之间调整，最长等待仍受max_wait_seconds限制。wait_seconds限1到120秒，同修订最多两次，仍尊重原decision_interval_seconds和每日判断额度。消息越多不意味着必须接话，wait到期也可以skip。
