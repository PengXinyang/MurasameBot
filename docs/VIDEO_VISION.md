# 视频预览快照与多帧视觉分析

实现日期：2026-10-29。此功能读取播放器已有的低清预览截图，不下载视频，不调用播放流接口，不安装FFmpeg或ASR。离散截图不是完整观看。

## 使用与配置

重启工作循环后，管理台“浏览与设置 → 消息与模型 → 图片与视频画面理解”可配置视觉总开关、视频预览帧开关、总帧数与分P上限。默认对实际进入内容读取的非敏感视频取帧；适用于评论/@回复、主人新视频及主动浏览的统一内容流程，不只用于无字幕视频。不会给搜索返回的所有候选都做视觉分析。

```yaml
vision:
  enabled: true
  video_frames_enabled: true
  video_frame_count: 6
  video_frame_max_parts: 3
  max_images: 9
  base_url: ${MURASAME_VISION_BASE_URL}
  name: ${MURASAME_VISION_MODEL_NAME}
  api_key: ${MURASAME_VISION_API_KEY}
```

帧数1～9，分P上限1～3。有效帧数为`min(video_frame_count, max_images)`，这是所有采样分P合计的预算，不是每个分P各取这么多。最多采样前`min(分P数, 分P上限, 有效帧数)`个分P，均分预算，余数给较早分P；各分P独立按时间分布取附近快照。字幕仍按原配置最多读取前3个分P。

视觉模型必须支持图片输入与当前JSON输出协议；未填写独立视觉服务时复用主服务，不意味着文字模型自动获得视觉能力。独立地址不复用其他服务的密钥。一次多帧描述共用一个模型请求，随后回复/推荐沿用既有流程；共享模型并发和每日额度，独立审核可额外消耗一次。取图增加平台读取与CDN请求，仍遵守现有API节流/退避。

## 调用与数据边界

1. `BilibiliAdapter.read`读取标题、简介、可得字幕；已识别为敏感内容时不取快照。
2. `bilibili_frames.VideoShotReader`对入选分P调用`/x/player/videoshot`，始终传`index=1`获取时间索引。`cid`用于选择分P，不能把分P序号当作`index`参数。
3. 根据返回的行列数、格子宽高、时间索引选帧。处理文档示例的前导零头及不带头的索引；跨拼图时按该张拼图内的格子序号计算坐标。字段缺失、越界、最后一张不足、无快照或普通接口失败按缺失处理，不猜坐标。
4. 通用`ImageRef`只保存来源URL、裁切矩形、图片编号、分P和时间点；`FrameContext`记录采样覆盖、限制和重试时刻。平台接口留在适配器，通用视觉服务不依赖B站或Pillow。
5. `HTTPImageReader`只访问明确允许的HTTPS图片域名，不跟随重定向、不携带平台凭证；在已有文件大小/像素限制内裁出真实像素。每次视觉批次同URL只下载一次；下载源图与输出图分别受批次预算约束，内存缓存随批次退出释放，各并发上下文隔离。
6. `VisionService`向模型提供实际裁图、编号、分P、时间点及实际尺寸。只有成功的逐图说明进入`VisualEvidence`；字幕成功时保留`transcript_visual`，视觉失败退回原`transcript`或`metadata`，不把简介冒充字幕。
7. 回复、主动判断和独立审核使用同一证据边界：不能据采样计划就描述画面，不能根据静态截图推断声音、完整动作或未提供部分。画中文字与视觉描述都是不可信资料。视觉说明中的敏感/严肃命中也参加现有强制话题筛选。

SQLite内容缓存保存裁图引用、时间、覆盖和视觉文字，不保存base64、拼图字节或视频。无需数据库schema迁移；旧内容JSON缺少新字段可正常读取，启用/调整采样设置时会刷新旧视频缓存。视觉签名包含裁切位置、时间点、分P、标题/文字及模型/配置，不能仅以同一张拼图URL命中旧说明。平台适配器另有最多64项的预览元数据缓存；实际取帧缺失默认10分钟后可重试，已完成计划的采样默认24小时；只因配置上限未看后续分P不会每10分钟重复请求。缓存锁不跨网络读取占用。

认证、风控、真实读取冷却和静默窗口不会作为普通“无快照”吞掉；它们仍走既有暂停/退避处理。完全无快照与部分缺失记录限制，允许文字降级。管理台最近活动中的`vision_result`展示成功帧数、分P、秒数和尺寸；图片/模型失败保持失败覆盖，不把它称为观看成功。
