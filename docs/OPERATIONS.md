# 配置、运行与排障

核对日期：2026-10-29。以下是可移植说明，不是对当前操作者私密配置、凭证或账号状态的快照。字段以[config.yml](../config.yml)和配置校验器为准。

## 安装与配置

在仓库根目录使用Python 3.12+：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,login]"
.\.venv\Scripts\python.exe run.py doctor
.\.venv\Scripts\python.exe run.py demo
```

`demo`使用假平台和场景模型，不代表连接了微信或B站。依赖锁见`requirements.lock`；Node/Edge仅用于可选管理台预览。

复制`.env.example`到`.env`，填写自己的模型基础地址、模型名、密钥和主人UID；不要提交。`config.local.yml`深合并覆盖模板，列表整体替换；环境变量只展开`${变量名}`。已有进程环境优先于`.env`，修改环境文件后重启。若本地覆盖已有`bindings`，仅改环境UID不一定改变实际绑定。

```dotenv
MURASAME_MODEL_BASE_URL=https://your-service.example/v1
MURASAME_MODEL_NAME=your-model-name
MURASAME_MODEL_API_KEY=your-private-key
MURASAME_OWNER_UID=your-bilibili-uid
```

兼容服务需支持`/chat/completions`和JSON对象输出；URL填基础路径。`model.max_output_tokens: null`默认不传`max_tokens`，使用服务默认值；需要时按实际服务文档显式配置，不把回复字数或字符预算当作模型输出token上限。视觉复用主模型时，主模型必须支持图片；另设视觉服务地址不会自动把主密钥发给不同服务。

绑定中的`person_id`是内部统一身份，`platform/external_id`为已核验的平台账户，`display_name`是显示名而非权限依据，`purpose`表示路由用途。主人换账号需同步检查绑定版本及旧任务。不要把真实UID写进公开示例。

## 两个独立登录

平台开关使用`platforms.<name>.enabled`，旧配置默认启用B站；QQ已具备主人私聊连接器和独立签名上报。管理台ReceiverManager可分别启停平台服务，QQ-only不会自动启动B站；禁用平台不参与新任务领取和发送，待处理数据保留。管理台外的CLI部署方式、登录凭证/连接参数变更与生命周期边界见[平台服务](PLATFORM_SERVICES.md)和[平台模块](PLATFORM_MODULES.md)。下列两个登录仅指B站AI社交账号与主人历史账号，QQ的NapCat登录见[QQ私聊](QQ_PRIVATE_CHAT.md)。

1. **AI发布账号**：`python run.py login`，用AI账号的B站App扫码；凭证在`.secrets/bilibili.json`。可配置预期`bilibili.robot_uid`防止误登。`python run.py doctor --online`只读检查登录。
2. **主人历史账号**：启动管理台，在独立的“主人足迹”页扫码，必须匹配已绑定主人；凭证在`.secrets/bilibili-owner.json`，不会覆盖AI登录。成功后启用采集，首次同步只建基线。

二维码由程序生成、需要用户用App扫码确认，不需要桌面浏览器。新扫码URL兼容`account.bilibili.com`和旧`passport.bilibili.com`的受限HTTPS地址；“扫码信息无效”曾是域名校验不兼容，不能一概归因于操作。二维码过期需重新生成；不要放宽到任意域名或公开二维码会话。

历史凭证客户端仅有GET白名单，Cookie自身仍需严格保管。当前没有自动Cookie刷新、验证码处理或完整Docker部署。重新登录并不能解释所有评论state17。

## QQ主动私聊

管理台“QQ → 私聊与消息 → 主动来找你聊聊”开启并保存；保持NapCat及QQ平台服务运行。默认每天09:00–22:00可判断，每30分钟检查，最多32次判断/2条计划，聊天后安静60分钟，主动消息至少间隔240分钟，AI最多延后120分钟或skip。QQ-only无需B站，原B站自主配置独立。计划/回执在QQ动作列表，关闭或修改QQ主动设置取消旧计划，实际送达和自然度需体验。详见[QQ主动私聊](QQ_AUTONOMY.md)。

## 启动与发布模式

2026-10-31：`serve`内置ReceiverManager，可在“运行概况 → 平台服务”分别启动QQ/B站；QQ回调随管理台托管，无需额外`qq-listen`进程。初次切换先停止旧独立worker/接收器，保留NapCat运行；`--with-worker`自动启动配置中开启的全部平台。保存平台设置开关也会同步启停。其他平台、在途请求和持久队列边界见[平台服务](PLATFORM_SERVICES.md)。

```powershell
# 先运行本机管理台，之后在页面分别启动QQ/B站
.\.venv\Scripts\python.exe run.py serve

# 自动启动已开启的平台接收服务及共用工作循环，可能真实发布
.\.venv\Scripts\python.exe run.py serve --with-worker

# 无管理台的后台循环；通常与上一条二选一
.\.venv\Scripts\python.exe run.py run
```

管理台默认`127.0.0.1:8766`，仅本机使用带token链接；不要把链接贴到日志或仓库。常规Docker端口映射、容器监听/鉴权及宿主机代理尚需单独完成，不能直接把127.0.0.1当容器外地址。

| 配置 | 含义 |
| --- | --- |
| `mode: reviewed`、`review.strategy: inline` | 默认，同次生成正文/表情与`can_send/review_reason`；未通过或无效进入人工草稿 |
| `review.strategy: independent` | 生成后独立模型复核，增加请求与额度消耗 |
| `mode: draft` | 全部人工审核，包括兴趣互动 |
| `mode: auto` | 跳过模型审核，仍需程序权限、主题、来源和额度检查 |

人工批准不绕过互关、敏感主题、来源及其保留期限、暂停、版本和实际发送前检查。发布板块区分私信、评论/@、点赞投币；没有生成动作的待重试事件不属于草稿。自主动态/择时私信和历史推荐初始关闭，普通私信默认开启但仅限互关。

“发布与草稿”中，待审消息有“审核并发送”，确定失败消息有“重发”。点击是对原正文的人工批准，更新本次投递时间与有效期并加入同一发送队列；需要工作循环运行，额度、间隔、主动时段和发送前检查仍生效，不会直接插队发送。原失败回执保存在活动记录的`manual_send`审计里，同一消息保留人工入队次数；重复点击不会生成多份动作。过期的投递期限可重新设置，但来源记忆、绑定、委托与观察权限不会刷新；失效时显示具体原因。失败委托只有原版本、原确定投递失败且来源仍有效才可恢复投递。

已受理、结果未知、发送中、取消或已经标记expired的动作不提供重发入口。unknown应先核对平台结果；人工确认失败后才可重发。state17属于已受理后的可见性问题，不会因新增按钮而重复发布。管理台接口只收ID，不能借此指定其他收件人。

“日记”“相处回顾”已经各自成为导航页，“记忆”不再混排它们。观看记录、扫码和观察设置统一在“主人足迹”。其中“允许根据观看线索写私人观察日记”默认开启，可独立关闭；需同时启用记忆维护、已授权历史同步和工作循环。默认23:00后空闲时按日整理基线后的新记录，到“日记”查看感想；想较快测试可把每日回顾时刻设置为几分钟后，再产生并同步新观看记录。首次基线不用于生成日记。没有新来源、额度为0或未授权时不调用模型。

观察日记不会发布或变成偏好、聊天事实、相处经历；普通回复也不自动读取它。来源清除/退出/解绑/过期会清除相关日记正文。观察日记支持查看来源与遗忘，遗忘日记保留观看记录且不会自动重建同批感想；观察正文和真人聊天档案是不同数据。

## 调度与额度

| 项目 | 当前模板默认 |
| --- | --- |
| 评论/@通知、私信、主人作品 | 15秒、30秒、90秒各自控制；实际间隔受工作循环/网络/退避影响 |
| 通知与私信收件 | 有界分页3页、每页30条，选取最新最多90条；截断显示警告，旧消息不保证追回 |
| 模型并发 | 4，管理台1～32；一个key也可并发，仍受服务端配额限制 |
| 模型每日总调用 | 150；记忆维护同时受自身每日10次及总额度约束 |
| 发送总额度/推荐额度 | 20/3；字段`daily_comments`实际包含多类动作，不只是文字评论 |
| 全局最小发送间隔 | 10秒，不表示可并发发送或平台官方允许频率 |
| 入站处理失败 | 60秒后重试，最多3次；不同用户独立消息可继续 |
| 主动浏览 | 默认关闭；普通探索需分区、星期、时段、每轮数等配置 |
| 自主发起 | 每30分钟可决策；每日8次；文字动态1次/6小时，主动私信2次/4小时，私聊空闲60分钟；09:00–22:00 |

计划使用`not_before`，最长默认延后120分钟，skip合法；失败、草稿、取消也可能占生成/决策预算。不要用重复生成来绕过限制。发送未知不会因事件重试而自动重发。

## 网络与请求控制

7890是外部代理软件提供的端口，项目不启动VPN。`http://127.0.0.1:7890`用于HTTP和HTTPS CONNECT；也可选SOCKS5/5h，单次使用一种协议。GFWList匹配且非例外才走代理，B站/QQ/微信/CDN及本机默认直连。规则更新失败保留旧规则；HTTPX不继承环境代理。

```powershell
# 判断路由，不访问这些目标；必要时可能读取/更新规则缓存
.\.venv\Scripts\python.exe run.py proxy-rules https://api.bilibili.com https://www.pixiv.net
.\.venv\Scripts\python.exe run.py proxy-rules --refresh
```

“代理规则更新失败”与扫码校验错误属于不同链路；检查代理实际协议与规则缓存，而非让国内平台统一绕行。管理台8766不是代理端口。

新增请求设置位于“消息与模型→B站请求与发送前静默”：GET至少间隔1秒，最多等5秒；收件身份缓存60秒，发送实时复验。读取-509/429按角色/通道从60秒递增退避，默认上限900秒，较长Retry-After最多遵守一天。AI/主人冷却隔离；共享数据库实例共用节流与收件轮询领取。

已入队自主动态/主动私信发送前60秒暂停通知、私信列表、主人作品、观察和探索读取，计划时间后15秒结束，实际受理后另留15秒；草稿不触发无限静默。新计划不足一分钟不能追溯补足，已在途请求不中断。必要身份/互关/最近来信预检仍执行，预检只越过静默，不越过真实冷却；发现主人新消息或无法确认覆盖时取消旧私信开场。

`retry_at`可推迟尚未写出的计划，不移动原定时间与过期时间。认证/验证码/写入风险保留强暂停，不能把unknown POST当确定失败重发。旧暂停须先看原因再人工恢复。脱敏请求记录默认7天/20000条，下一次记录时清理，不保存参数、正文、Cookie和二维码key。

## 功能验收与排障

先跑本地测试与只读检查，再由操作者逐项验证真实发布。`--with-worker`和`run`有真实动作可能；仅测试生成可用draft模式。首次通知/私信/主人内容建立基线，应在基线后发送新测试消息。主人也必须互关。

- **未回复**：查工作循环、总暂停/平台暂停/通道冷却/静默、收件基线与水位、消息年龄和90条截断；再看事件重试、同用户前序、模型额度/并发、主题跳过、草稿、过期与队列间隔。缺少发布记录不等于没收到事件。
- **模型空正文/JSON错误**：HTTP200不保证结构可用；检查脱敏的finish_reason、长度/计数及错误类型，确认模型服务支持所需JSON格式。不要把推理内容当正文，不盲目设超出服务限制的输出长度。
- **评论已受理但别人看不到**：使用管理台只读核查或`python run.py comment-check <本地动作ID>`，有限分页未找到不能断定删除。state17、state11、登录视角state0与第三方可见不同；不自动重发。
- **真人同文成功、程序不成功**：对比当前成功网页的`/x/v2/reply/add`、oid/type/root/parent、at映射、实时WBI签名、Origin/视频Referer、账号会话与路由。不要复制抓包签名/时间戳/设备令牌，不提交Cookie、CSRF、HAR或“复制为cURL”。先前签名修复仅有一个用户确认成功场景。
- **历史/吃醋不触发**：检查独立主人登录、首次基线、观察新增和保留窗口、私聊授权/互关、主动私信开关及空闲/时段。历史推荐另需启用、匹配允许公开的主题及浏览推荐窗口；不是读取整份清单后任意公开评论。
- **主人观察失效**：新计划采用授权版本+引用ID，不因正常历史刷新取消。撤权、清除、引用过期或用途权限变化仍拦截；旧版仅存快照的消息需重新生成，按钮不自动迁移来源或强行补回历史。
- **摘要重建/记忆版本失效**：同文摘要重建已改为新版本产物；此前失败过的范围升级后可再点一次重建。普通推荐及同次评论/互动现已携带记忆版本，删除或更正后旧动作不再发送。`memory_revision_missing`说明升级前动作没有可核验版本，须重新生成；`memory_sources_invalidated`说明使用的版本已失效。人工重发不会补填或刷新这些来源版本。
- **授权美图不发布**：检查来源会话、时刻/宽限、安全元数据、授权作品/画师ID与证据、有效期、`delivery`及独立开关。署名不代替授权；当前没有完整像素级视觉筛选。主人转发和主人评论是四个独立开关，首次不回放历史作品。

私密运行数据、诊断导出和抓包保留在仓库外；只在开发日志写脱敏结论与验证边界。完整测试方式与本次结果见[VALIDATION.md](VALIDATION.md)。

## 投币`-401`与视觉JSON错误（2026-10-30）

2026-10-31补充：用户确认浏览器手动投币成功；程序现已补齐其成功请求中的两组URL描述及页面来源/统计字段，投币CSRF仅在表单中使用本地当前值。单币和独立点赞策略保留，不能据模拟测试保证真实平台已经恢复。抓包的HTTP200与响应头状态0说明该次浏览器请求成功，不代表程序请求也成功；CORS/trace等响应头不应复制成请求头。抓包中的Cookie、CSRF及原始文件不纳入代码、日志或公开文档。

完整重启最新版本后，先检查AI登录状态；既有暂停不会由升级自动清除。查看原失败原因后恢复工作，仅对一条**确定失败**且仍满足来源/额度条件的投币动作进行人工验收；已受理、已经投过币或unknown不要重投。若仍为-401，关闭视频投币开关后再恢复其他工作，保留该次脱敏错误时间/码，继续核对会话和网络；不要连续重发。浏览器捕获连接了本机7890，程序国内默认直连，这个差异尚未验证因果，不自动调整代理，也不要求仅因升级重新扫码。

- B站业务码`-401`表示请求未通过认证/平台校验，不是HTTP401，也不是硬币不足；硬币不足通常为`-104`，投币间隔过短为`34004`。登录有效不等于互动请求一定通过风控。网页投币需要有效`buvid3`，旧扫码文件可能仅含账号凭证；现在缺失时在发送前通过真实B站接口取得，保留10秒默认间隔和单币限制。现有设备值不因拒绝而自动轮换，拒绝的POST不自动重试。此修复不保证所有`-401`消失；若继续拒绝，可对比同账号浏览器成功请求的来源/会话，不复制或公布Cookie、CSRF、设备值、签名或原始抓包。
- 出现`-401`会触发既有平台暂停。升级重启后查看管理台顶部，若显示“恢复工作”，检查账号状态后点击恢复，再对一条确定失败动作手动发送；不重复点击或重发unknown。无需仅因这次升级重新扫码；真正登录过期再重新登录。
- 真实设备值放在登录凭证同目录的独立`.device.json`私密缓存，按登录会话摘要隔离，发送任务重建后复用，不覆写扫码文件、不输出到日志或上传到仓库。这个文件属于凭证材料；原`.secrets/`目录已整体忽略。缓存损坏时明确停止，不能靠不断生成设备值重试平台拒绝。
- `describe_images`的HTTP200只说明服务返回，`invalid_content_json`表示正文不能按JSON对象解析。`finish_reason=stop`不是长度截断；不要直接缩短视频或提高token上限。新诊断包含`json_error_reason`和行列位置，不保存原文。视觉专用的尾逗号/原始换行可在本地规范化；内容歧义、缺字段或截断仍拒绝，不用另一轮模型修补。
- `vision_result`分别显示图片下载数量与有效识别数量及失败阶段；下载6/6、识别0/6表示拿到图片但没有可信视觉说明。失败缓存默认10分钟，可等后续内容读取再试；没有背景无限重试或自动发布。话题“未知/敏感/非主人严肃”现在分别提示，未知仍跳过，不表示视频已被确认敏感。旧审计文本保持原样，查看重启后的新记录。

协议参考：[投币与buvid3要求](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/video/action.md)、[真实设备字段获取](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/misc/buvid3_4.md)。这些是社区协议记录，不是B站稳定性承诺。

## 视频预览帧

### 仅推荐与播放量/评论数（2026-10-30）

B站“浏览与设置”新增“仅给主人推荐（不主动评论或接话）”、播放量门槛和评论数门槛。默认仅推荐开启，两个门槛分别为8000、20，均为严格大于：8000播放或20条评论不满足，8001播放且21条评论才满足。统计未知也不放行，后台按现有候选/重试策略继续寻找，不承诺一定找到合格视频。

门槛也用于全部明确委托及私聊视频结果，普通视频回复、主人新作品不豁免。只有用户在视频评论区直接@机器人后的对应回复可豁免统计；敏感话题和审核规则仍保留。图文/动态没有视频播放量，两个数值不适用于它们，但仅推荐开关仍阻止主动普通评论。开启后旧队列/人工发送也检查，关闭仅推荐后恢复原有主动评论/接话独立开关；点赞、投币、自主动态与转发仍用各自开关。旧缓存无统计时在内容再次读取时刷新，开发不会替用户补发旧消息。

```yaml
browsing:
  recommendation_only: true
  min_video_views: 8000
  min_video_comments: 20
```

工作循环启动后，在“浏览与设置 → 消息与模型 → 图片与视频画面理解”调整视频预览帧开关、最多帧数和前几个分P。默认最多6帧/前3个分P，仍受视觉总开关及图片总数限制；不需要额外服务或FFmpeg，但模型必须支持真实图片输入。可在本地配置独立`vision.base_url/name/api_key`。模型说明和最近活动保留分P、时间点、尺寸与失败覆盖；没有快照时使用标题/简介/字幕，不会下载视频补齐。升级后须完整重启旧工作循环，勿同时启动第二个发送进程。配置、调用与验收边界见[视频视觉](VIDEO_VISION.md)。

## 心情、线索与公开角色互动

完整重启后打开“心情与线索”，确认记录与公开表达开关、有效期和跟进范围。默认允许把主人的私人线索转为不含具体行为的公开感受；需要自动公开发布时，还须在“浏览与设置 → 消息与模型”开启自主文字动态；主动私信另开对应总开关且须互关。默认私信安静期60分钟、动态冷却360分钟等原限制仍生效，最早跟进15分钟不代表届时一定发送。普通回复的记录判断共用原生成，不追加一次审核调用。

测试可让主人发送一条明确的轻松社交信息，先检查是否产生带原文来源的短期状态，再发送解释/澄清，核对状态结束、旧草稿取消。主动计划也进入“发布与草稿”；需要人工时使用原审核按钮。公开情绪测试应检查没有私聊原文、具体观看内容或未知第三方身份；详细配置/生命周期与验证边界见[社交状态](SOCIAL_STATES.md)。
